# eDHR 列表页 UI 规范

## 1. 文档目的

本文档是 eDHR 前端列表类页面的统一开发和验收规范。后续开发普通列表页、RDO 列表页或带分类列表页时，默认遵守本文档，不得自行设计新的页面骨架、表格风格或操作图标体系。

本文档基于当前项目中已经落地并重复使用的页面模式整理，主要参考：

- `gmp-platform/frontend/src/pages/master-data/ProcessModelingPage.tsx`：普通列表页及工艺建模列表。
- `gmp-platform/frontend/src/pages/master-data/ProductModelingPage.tsx`：产品及制程版本的 RDO 列表。
- `gmp-platform/frontend/src/pages/master-data/TemplateModelingPage.tsx`：模板建模列表及版本列表。
- `gmp-platform/frontend/src/pages/master-data/DocumentManagementPage.tsx`：带分类列表页、主表/版本子表和分类操作。
- `gmp-platform/frontend/src/components/shared/AppLayout.tsx`：系统壳层、导航、标签页和基础色彩。
- `gmp-platform/frontend/src/components/AppDialog.tsx`、`ConfirmDialog.tsx`、`EmptyState.tsx`、`TableSkeleton.tsx`：公共交互组件。

“RDO 列表页”仅表示页面包含带 revision/version 语义的对象及其版本层级。普通列表页和带分类列表页不能因为使用了表格就统称为 RDO 页面。

## 2. 统一设计基线

### 2.0 页面标题与应用壳层

- 列表页运行在 `AppLayout` 提供的顶部导航、标签栏和内容区域中，页面标题以应用标签栏中的菜单名称为准。
- 普通列表页、RDO 列表页和生产准备列表页不得在查询面板上方重复插入独立的大标题或副标题；这样会改变同类页面的可用高度和视觉节奏。
- `PageHeader` 仅用于确实需要页内标题、面包屑或页内操作的内容型页面（例如详情、向导或独立工作区），使用前应确认不会与应用壳层标题重复。
- 页面若需要补充来源或派生关系，应放在列表工具栏的辅助文字位置，不得用副标题替代标准列表骨架。

### 2.1 页面容器

- 页面内容位于 `AppLayout` 提供的内容区域内，不自行实现侧边栏、顶部导航、面包屑或标签栏。
- 页面背景使用项目浅灰背景，内容区域使用白色面板。
- 桌面端列表页面优先使用纵向 Flex 布局：查询面板、列表面板上下排列，列表面板占据剩余高度。
- 页面之间使用 `gap: 12px`（MUI `1.5`）或现有页面已经使用的等效间距。
- 面板边框使用 `1px solid #e4e7ed`，圆角使用 MUI `borderRadius: 1`，不得引入大圆角、渐变或卡片套卡片。
- 长列表面板应设置 `minHeight: 0`、`overflow: hidden`，表格内容在 `TableContainer` 内滚动。

### 2.2 色彩和文字

| 用途 | 规范值 |
| --- | --- |
| 主色 | `#1890ff` |
| 主色浅背景/选中背景 | `#e8f4ff` |
| 页面背景 | `#f6f8f9` |
| 表头背景 | `#f5f7fa` |
| 主文字 | `#303133` |
| 次要文字 | `#606266` |
| 禁用/空状态文字 | `#909399` |
| 分割线/面板边框 | `#e4e7ed` |
| 危险操作 | `#ff4d4f` 或主题 error 色 |

- 优先使用 MUI theme 和现有 `COLORS`，只有项目尚未提供 token 时才使用上述已有值。
- 不使用新的主色、阴影体系、字体体系或渐变。
- 页面标题使用项目现有 Typography 层级；列表内容不得使用过大的展示型标题。
- 表格数据优先使用 `body2`，辅助信息使用 `caption` 和次要文字色。

### 2.3 图标和按钮

- 图标优先使用项目已安装的 MUI Icons；不得手绘 SVG 或引入另一套图标库。
- 只有明确命令才使用带文字按钮，例如“新增”“查询”“重置”“保存”。
- 表格操作优先使用图标按钮，并通过 `Tooltip` 说明动作；按钮必须提供 `aria-label`。
- 工具栏图标按钮统一为约 `36 x 36px`，白色背景、`1px solid #e4e7ed`、小圆角。
- 主操作使用 `variant="contained"`，次操作使用 `variant="outlined"`，取消使用普通文本按钮。
- 危险操作使用 error 色，并通过 `ConfirmDialog` 二次确认。

## 3. 三类页面模板

### 3.1 普通列表页

典型页面：物料管理、工序管理、工艺路线管理等不包含版本子表的列表。

页面结构固定为：

```text
页面内容
├─ 查询面板
│  ├─ 查询字段
│  └─ 右侧：重置、查询
└─ 列表面板
   ├─ 工具栏：字段设置/批量工具（按业务需要） + 右侧新增
   ├─ 表格
   └─ 底栏：总数 + 分页 + 每页条数（按既有页面需要）
```

规则：

- 查询面板是白色边框面板，内边距通常为 `16px`，查询字段使用 `size="small"`，输入控件高度统一为 `40px`。
- 查询字段按桌面端三列网格排列；查询和重置按钮靠右对齐。移动端改为单列。
- 查询按钮使用蓝色实心按钮，重置按钮使用蓝色描边按钮，二者宽度通常为 `80px`、高度 `40px`。
- 列表面板为独立白色边框面板，不能直接把 `Table` 放在页面背景上。
- 有新增能力时，“新增”位于列表工具栏右侧；文字根据业务使用“新增”或“新建”，同一页面不得混用。
- 表格为空时使用统一空状态；简单列表可以在表格行中居中显示“暂无数据”，复杂页面优先使用 `EmptyState`。
- 列表底栏显示“共 N 条数据”，左侧放总数，右侧放分页和每页条数控件。

### 3.2 RDO 列表页

典型页面：产品管理、模板管理、文档版本管理中的版本层。

RDO 页面是在普通列表页骨架上增加 revision/version 层级，不改变普通列表页的基础视觉规范：

```text
查询面板
└─ RDO 主表面板
   ├─ 工具栏：字段设置、展开/收起、其他主表工具 + 新增
   ├─ 主表（对象/主版本载体）
   ├─ 展开后的版本子表（revision/version）
   └─ 底栏：主表总数 + 分页
```

规则：

- RDO 主表与版本子表必须明确区分，主表行和版本行不得混为一张无层级的普通表。
- 展开/收起使用 `UnfoldMoreRounded` 和 `UnfoldLessRounded`，工具栏提供“全部展开”和“全部收起”（业务确实存在层级时）。
- RDO 版本列应体现版本、状态、生效信息等版本语义；不需要版本语义的页面不得套用 RDO 结构。
- 主表和版本子表必须共享表头风格、列宽逻辑、滚动方式和操作列对齐方式。
- 字段设置如果同时影响主表和版本子表，使用带“主表/子表”切换的 Popover；不能把字段配置散落到多个不同样式的菜单中。
- 版本状态使用 `StatusBadge` 或项目现有状态展示组件，不自行创建新的彩色标签体系。
- 展开行、版本行的操作按钮与同类页面保持一致：查看/预览、编辑、复制、删除等动作按业务实际提供。
- 主表和子表的操作列必须保持右侧对齐；横向滚动时操作列应具有稳定宽度，不能随内容漂移。

### 3.3 带分类列表页

典型页面：表单管理、文档管理。

页面结构固定为：

```text
页面内容
├─ 左侧分类面板
│  ├─ 系统分类/业务分类
│  ├─ 当前选中态
│  └─ 分类编辑、删除、拖拽排序（按业务需要）
└─ 右侧列表区域
   ├─ 查询面板
   └─ 列表面板
      ├─ 字段设置/展开收起 + 新增
      ├─ 表格或 RDO 主表/版本子表
      └─ 总数、分页、每页条数
```

规则：

- 桌面端采用左侧分类、右侧列表的两栏布局；现有页面的分类栏宽度约为 `260px`，两栏间距为 `12px`。
- 分类面板本身是白色边框面板，分类项高度约 `40px`，选中背景使用 `#e8f4ff`，文字使用主色。
- 系统分类与业务分类必须区分权限和操作能力；系统分类不能显示编辑/删除图标。
- 分类项中的编辑、删除等图标必须阻止事件冒泡，不能误触发分类切换。
- 右侧列表仍然严格遵守普通列表或 RDO 列表的表格规范，不因增加分类栏而另起一套样式。
- 如果分类页面同时有版本层级，应组合使用“带分类列表页 + RDO 列表页”两套规则。
- 分类数量、未分类入口、拖拽排序等交互必须有明确空状态和错误反馈。

## 4. 统一表格规范

### 4.1 表格容器

- 表格必须放入 `TableContainer`，列表面板负责边框、圆角、背景和整体高度。
- 需要固定表头时使用 `stickyHeader`。
- 长列表使用 `overflow: auto`；列表面板内部不得让整个页面出现无意义的横向滚动。
- 多列页面使用 `tableLayout: 'fixed'`、明确列宽和最小宽度；列宽不能完全由内容随机撑开。
- 数据少、状态为空或加载中时，表格区域仍保持稳定高度，避免页面跳动。

### 4.2 表头

- 表头背景统一为 `#f5f7fa`。
- 表头文字使用 `#606266`，字重 `600`，不换行。
- 表头必须使用固定 `48px` 高度（`height: 48`、`py: 0`），不得只依赖 MUI 默认 `size` 密度或使用页面自定义高度。
- 表头底边使用 `1px solid #e4e7ed`。
- 操作列表头与操作列内容使用同一宽度和同一对齐策略。
- `TableHead` 的表头行必须通过统一的行级选择器（例如 `TableRow sx={{ '& .MuiTableCell-root': tableHeaderCellSx }}`）覆盖全部表头单元格；单个单元格只能叠加列宽、对齐和 sticky 定位，不得产生另一套表头 token。
- sticky 表头和普通表头必须使用相同的背景、文字、边框和 `48px` 高度；固定操作列表头也必须显式保持 `#f5f7fa` 背景。

### 4.3 表体和行

- 普通数据行必须使用固定 `40px` 高度（`height: 40`、`py: 0.5`、底边 `1px solid #ebeef5`），各页面不得因状态徽标、辅助说明或纵向堆叠内容把行撑高；需要展示辅助信息时应使用同一行内布局、截断或 Tooltip。
- 同一列的内容保持同一对齐方式；编号、名称、状态、数量和时间列不得随意混合对齐。
- 长文本使用 `noWrap`、省略号或二级信息展示；不得撑破表格。
- 产品/物料等主名称可以使用主文字，编码等辅助信息使用 `caption` 和次要文字色。
- 状态统一使用项目状态组件或既定文字映射；不得在不同页面为同一业务状态使用不同中文含义。
- 加载、错误、空数据状态需要占满表格列数，并保持垂直居中。

### 4.4 操作列

- 列表行如果定义了“点击行查看详情”，统一由右侧详情抽屉承载该对象的“数据信息/数据审计”页签；同一对象不得同时在操作列重复提供独立的“数据审计”入口。
- 仅当页面存在与行点击详情不同的独立动作（例如编辑、删除、开始、关闭）时才保留操作列；纯查看型列表可以省略操作列，避免同一交互出现两套入口。

操作列是所有列表页最需要统一的区域。默认图标语义如下，具体动作按页面能力取舍：

| 动作 | 推荐图标 | Tooltip 文案 | 颜色/规则 |
| --- | --- | --- | --- |
| 查看/详情 | `VisibilityOutlined` 或既有查看图标 | 查看 | 普通色 |
| 编辑 | `Edit` | 编辑 | 普通色 |
| 复制/从现有创建 | `ContentCopy` | 复制 | 普通色 |
| 预览文件 | `PreviewOutlined` | 预览文件 | 无文件时禁用 |
| 新增版本/子项 | `PlaylistAdd` 或既有新增图标 | 新增版本/新增子项 | 普通色 |
| 展开/收起 | `ExpandMore` / `ExpandLess` | 展开/收起 | 用于层级行 |
| 删除 | `Delete` | 删除 | error 色，必须确认 |
| 取消/停用 | `Cancel` 或既有取消图标 | 取消/停用 | 危险动作，必须确认 |
| DHR 查看 | `DescriptionOutlined` | DHR | 未开工时禁用 |
| 执行详情 | `PlayCircleOutline` | 执行详情 | 未开工时禁用 |
| 提前结束 | `StopCircleOutlined` | 结束 | warning 色，必须确认并填写原因 |
| 开始/开工 | `PlayArrow` | 开始/开工 | 仅用于可启动对象 |
| 完成/确认 | `Check` | 完成/确认 | 仅用于可完成对象 |
| 关闭 | `Close` | 关闭 | 仅用于可关闭对象 |

- 操作按钮顺序优先为：查看/预览、编辑、复制/新增子项、状态动作、删除/取消。
- 每个操作必须由业务状态控制显隐和禁用，不得只依靠前端隐藏绕过后端权限或状态校验。
- 图标按钮使用 `IconButton size="small"`，每个按钮必须有 `Tooltip`；不可见文字只作为 Tooltip 和无障碍标签存在。
- 表格操作按钮不使用 `Stack spacing` 或 `gap` 额外拉开距离；需要视觉分组时使用状态显隐、Tooltip 和固定顺序，而不是压缩点击区域或增加不一致的间距。
- 多于 4 个操作时，应评估使用更多菜单，避免操作列过宽；但不得为单个页面引入与项目不一致的新菜单样式。
- 操作列宽度必须固定，并在表头、主表行、子表行之间保持一致。
- 只要表格可能横向滚动，操作列必须固定在右侧：表头和数据单元格都使用 `position: 'sticky'`、`right: 0`、同一固定宽度、匹配的背景色和右侧分隔阴影；不得只固定宽度而让操作列随横向滚动离开可视区。
- 工单管理和批次管理主列表的状态列紧邻操作列左侧，并与操作列组成连续固定区；状态列的 `right` 等于操作列宽度，固定区只在最左侧保留滚动阴影，两列之间不得重复添加阴影或间距。该规则仅适用于这两个页面，其他列表页的状态列默认不固定。
- 新页面必须基于同类页面的共性模式选择操作列样式和图标映射，不能为相同动作自由选择不同图标变体。实现前至少核对一个普通列表、一个 RDO 列表和一个与当前业务同类的页面，提炼共同约束后写入本规范；任何单个页面都只能作为证据，不是唯一模板。
- 操作列宽度由同时可见的图标数量决定，而不是由页面名称或某个历史实现决定。表格 `IconButton size="small"` 以 `32px` 点击区域计算，操作列不额外设置图标间距，并保留左右各 `16px` 安全边距：`1` 个图标为 `64px`、`2` 个为 `96px`、`3` 个为 `128px`、`4` 个为 `160px`。超过 `4` 个操作必须使用统一的更多菜单，不得无限加宽。
- 同一张主表、子表或展开表按可能同时出现的最大图标数选择宽度；状态不适用的图标仍保留禁用占位，宽度和按钮位置不得跳变。共享列宽的主/子表必须使用同一档位。
- 行点击已经承载详情时，操作顺序为“查看类入口（如 DHR、执行详情）→ 编辑/新增类动作 → 状态动作（如结束）→ 危险动作（如取消）”。状态不适用的入口保留禁用占位时，也不得改变其余按钮的位置。
- 删除、取消、关闭等不可逆或高影响动作必须使用 `ConfirmDialog`，禁止使用浏览器原生 `window.confirm`。
- 独立列表页即使尚未迁移到可配置列，也必须使用上述图标、Tooltip、居中对齐和宽度档位；只有不产生横向滚动的小型固定表格可以不使用右侧 sticky。仪表盘卡片、弹窗内临时编辑表和设计器内嵌表不属于独立列表页，按其所在工作区的紧凑交互处理。

## 5. 查询、工具栏和分页

### 5.1 查询区域

- 查询字段采用带 label 的 MUI `TextField`、`Select`、`Autocomplete` 等既有控件。
- 输入框高度统一为 `40px`；查询条件较多时采用三列网格，移动端单列堆叠。
- 回车可以触发查询，但必须与点击“查询”使用同一提交逻辑。
- “重置”必须清空输入条件、恢复第一页并重新查询；不能只清空视觉值。
- 查询条件与已提交条件分离时，沿用现有页面的 `keyword/submittedKeyword` 模式，避免每次输入都请求接口。

### 5.2 列表工具栏

- 工具栏高度约 `48px`，左右内边距约 `16px`，底部使用分割线。
- 左侧放字段设置、展开/收起、批量或视图工具；右侧放新增等主操作。
- 字段设置使用列图标叠加调整图标的既有样式，Tooltip 为“字段设置”。
- 字段设置 Popover 中支持显隐；有明确需求时支持拖拽排序和列宽调整，并保存到当前用户偏好。
- 工具栏不放与当前列表无关的说明性大段文字；业务说明应放在详情、帮助或页面提示中。

### 5.3 分页底栏

- 列表底栏高度约 `56px`，顶部有分割线，左右内边距约 `16px`。
- 左侧显示“共 N 条数据”。
- 右侧显示 `Pagination size="small"`；需要换页条数时增加统一的 Select。
- 没有多页数据时可以隐藏分页控件，但总数位置和底栏高度保持稳定。
- 页码变化应回到对应查询状态，不丢失筛选条件。

## 6. 详情抽屉、弹窗、反馈和状态

- 列表行点击查看详情时统一使用右侧 `Drawer`，不得使用居中 `Dialog`；桌面端宽度统一为 `560px`，移动端为 `100vw`，抽屉覆盖完整视口高度。
- 详情抽屉顶部使用 `subtitle1` 标题和右侧关闭图标，下方放置“数据信息/数据审计”页签；内容区使用 `#f7f9fc` 背景、`16px` 内边距并独立纵向滚动，不设置底部“关闭”文字按钮。
- 详情抽屉内的信息区使用两列响应式网格和统一 `DetailSection`；审计记录使用适合窄栏阅读的折叠项，不得放置需要横向滚动的大型审计表格。
- 客户可见的审计快照不得直接展示原始 JSON 或内部英文字段 key；同一业务域应使用共享映射统一转换为中文字段名、稳定字段顺序和业务枚举值，空快照显示“无”、空字段值显示“-”，且展示转换不得改写后端原始审计证据。
- 新增、编辑、拆分、预览、确认等集中任务优先使用 `AppDialog`，保持统一关闭按钮、圆角和尺寸；不得把“查看详情”归入此规则。
- 表单弹窗结构使用 `DialogTitle`、`DialogContent`、`DialogActions`；操作按钮顺序为取消在左、主操作在右。
- 表单弹窗的 `DialogContent` 必须使用 `dividers`，让标题区和底部操作区与内容区有稳定横线分隔；不得使用页面自定义阴影或额外边框替代。
- 表单字段不得直接裸放在 `DialogContent` 中。即使只有一组字段，也使用与主数据页面一致的 `DetailSection` 或同级分组容器承载，常规分组标题为“基本信息”；复杂表单按业务含义拆成多个分组。
- 弹窗字段默认使用 `size="small"`，分组内采用 `12px` 垂直间距或两列响应式网格；`DialogContent` 内边距保持桌面端左右 `24px`、上下 `16px`，`DialogActions` 保持左右 `24px`、上下 `12px`。
- `DialogTitle` 使用统一的 `h6`/`subtitle1` 层级，标题颜色为 `#303133`、字重为 `600`；标题区域内边距应与公共关闭按钮兼容，不在单个页面另起一套标题视觉。
- 标题下的补充说明使用 `caption` 层级和 `#909399` 次要文字色，只有确有业务帮助价值时才添加，避免使用大段说明文字。
- 异步保存时禁用重复提交，并显示“保存中...”或公共加载状态。
- 删除、取消、关闭等危险动作使用 `ConfirmDialog`，危险按钮使用 error 色。
- 成功和失败反馈使用项目 `SnackbarProvider` 或现有 `Snackbar + Alert` 模式，不使用 `alert()`。
- 列表加载优先使用 `TableSkeleton` 或同类页面已有的稳定加载态；不得让表头和布局因加载态消失而跳动。
- 空状态要说明“暂无数据”；如果用户可以直接创建，优先提供对应操作入口。
- 错误状态要显示可理解的业务文案，保留重试或重新查询路径；不得只显示原始异常对象。

## 7. 响应式和可访问性

- 桌面端优先保证 1280px 以上页面的完整结构；中小屏幕通过单列查询、可滚动表格和收缩操作区适配。
- 固定格式元素必须有稳定尺寸，不能因 Tooltip、加载文字或状态变化改变布局。
- 所有图标按钮需要 `Tooltip` 和 `aria-label`；纯图标不能只依赖视觉识别。
- 表格必须有表头；交互行和按钮应保持键盘可达。
- 文本不得溢出父容器；名称、编码和备注等长文本使用省略或换行规则。
- 页面不使用大面积渐变、装饰性光晕或与现有系统无关的视觉元素。

## 8. 开发约束

- 新列表页必须先选择本文档中的一种页面模板，再开始编码。
- 优先复用公共组件和同类页面的结构；如果公共组件缺失，先采用现有成熟页面的局部模式，不自行创造第三套规范。
- 页面代码中的 `sx` 应与同类页面保持一致；重复出现的表头、工具栏、操作列样式应提取为公共组件或共享样式，而不是继续复制出更多变体。
- 普通列表页不得加入版本树；RDO 页面不得省略主表/版本层级；带分类页面不得把分类筛选伪装成普通下拉框而丢失左侧分类工作区。
- 页面名称和业务术语必须准确使用：只有带 revision/version 的对象才称为 RDO/版本对象，普通工单、批次、物料等不称为 RDO。
- 页面实现必须同时满足后端接口权限、前端菜单权限和业务状态权限；前端菜单显示不等于接口授权。

## 9. 交付前检查清单

### 页面结构

- [ ] 已明确页面属于普通列表、RDO 列表、带分类列表，或两者组合。

- [ ] 页面没有自定义侧边栏、顶部导航或另一套标签页。

### 表格和操作

- [ ] 表头颜色、文字、边框、行密度和操作列对齐与既有页面一致。
- [ ] 表格使用稳定列宽、滚动容器和空/加载/错误状态。
- [ ] 操作图标、顺序、Tooltip、颜色和确认方式符合统一表。
- [ ] 已按普通列表、RDO 列表、业务同类列表三类证据核对操作列宽度、固定方式、图标变体和动作顺序；没有把任一单页当作唯一标准。

- [ ] 查询、回车查询、重置、分页和每页条数行为一致。
- [ ] 行点击详情使用统一右侧抽屉；新增、编辑等任务使用 `AppDialog`；危险动作使用 `ConfirmDialog`，反馈使用 Snackbar/Alert。

## 10. 规范变更

本文档是当前列表页开发的默认基线。若新业务确实无法适配，必须在开发前说明不适配的业务原因、影响范围和替代方案；不能仅因为实现方便就绕开既有结构。新增公共模式或修改操作图标语义时，应同步更新本文档，并检查至少一个普通列表页、一个 RDO 列表页和一个带分类列表页。
